1. Problem Statement

Modern software delivery teams face a common challenge: how to ship code from a developer's laptop to production reliably, repeatedly, and safely — without manual steps, downtime, or security risks. The traditional approach of manual builds, manual deployments, and reactive monitoring is slow, error-prone, and cannot scale to multiple daily releases.

This capstone project addresses that challenge by building a complete, production-ready DevOps automation platform for a Node.js web application. The platform must:

  • Automate the full software delivery lifecycle from code commit to production deployment
  • Containerize the application and orchestrate it on Kubernetes with zero-downtime deployments
  • Provision infrastructure as code using Ansible and Terraform
  • Provide full observability: metrics (Prometheus + Grafana), centralized logging (ELK stack)
  • Integrate security scanning at every stage (Trivy, HashiCorp Vault)
  • Support advanced deployment strategies: Blue-Green, Canary, Rolling Update
  • Demonstrate disaster recovery with RTO under 5 minutes
  • Be fully version-controlled in Git with organized, documented source code
Application: A Node.js + Express REST API (devops-capstone-app) exposing /health, /api/info, /api/status, and /metrics (Prometheus format) endpoints — a representative microservice used as the deployment target throughout the platform.

9.2 HashiCorp Vault Secret Management

# Start Vault
docker run -d --name vault -p 8200:8200 \
    -e VAULT_DEV_ROOT_TOKEN_ID=root hashicorp/vault:1.15.2
export VAULT_ADDR="http://localhost:8200" VAULT_TOKEN="root"

# Store secrets
bash scripts/secret-management.sh init
# Secrets stored: DB_PASSWORD, API_KEY, JWT_SECRET

# Inject into Kubernetes
bash scripts/secret-management.sh inject capstone
# Secret 'capstone-secrets' created in namespace: capstone

# Rotate secrets
bash scripts/secret-management.sh rotate
# New API_KEY generated and injected. Deployment restarted.
Key Security Principle: No secrets committed to Git. All credentials stored in Vault with read-only app token (24h TTL, renewable). KV v2 versioning enables recovery of previous values.

13. Challenges & Solutions

ChallengeSolution
Trivy DB download slow on CI (adds 2min)Mounted Trivy cache dir as Docker volume; reused on subsequent runs
ArgoCD could not reach private GitHub repoAdded SSH deploy key to GitHub and ArgoCD credentials store
Elasticsearch OOM on 2GB RAM VMSet ES_JAVA_OPTS="-Xms256m -Xmx512m" in Docker Compose

HPA not triggering — metrics-server not installedminikube addons enable metrics-server

14. Conclusions

This capstone project successfully delivered a complete, production-ready DevOps automation platform integrating every layer of the modern DevOps stack.

What Was Built

  • Application: Node.js REST API with Prometheus metrics endpoint, 95%+ test coverage
  • CI/CD: GitHub Actions (3 jobs) + Jenkins (parameterized), from commit to deployment in 93 seconds
  • Containerization: Multi-stage Dockerfile, non-root user, 142 MB image, 0 CRITICAL vulnerabilities
  • Kubernetes: 3-replica deployment, HPA auto-scaling (2→10 pods), Blue-Green, Canary, Rolling update
  • IaC: Ansible playbook (provisions 3 servers in 4 minutes), Terraform (4 resources, full lifecycle)
  • Observability: Prometheus scraping every 15s, Grafana dashboards, ELK centralized logging, AlertManager
  • Security: Trivy in every CI run (0 CRITICAL), Vault for secret management and rotation
  • Disaster Recovery: Automated backup + restore with RTO of 87 seconds (target was 5 minutes)

Key Learnings

  • GitOps fundamentally changes operations: Git becomes the single source of truth, eliminating manual kubectl commands
  • Security must be shifted left into the pipeline — scanning at build time catches issues before they reach users
  • You cannot manage what you cannot measure: Prometheus + Grafana make system health immediately visible
  • Canary deployments are the safest way to validate new versions — real user traffic with controlled blast radius
  • An untested DR procedure is not a DR procedure — the 87-second RTO was proven by actually running the drill
